# Notebook

A light, offline-first notes app for Android, built with HTML, CSS and JavaScript and packaged as a native app with Capacitor.

The interface is a light editorial design — warm paper, ink text, hairline rules, a single burnt-orange accent. No frameworks, no build step for the web layer, no server, and no network calls at runtime.

## Screens

| Screen | What it does |
| --- | --- |
| **Notes** | The list. Tap a note to reveal Share and Copy; tap again to edit inline. Swipe left to delete. |
| **Settings** | Vibration toggle, persisted across restarts. Reachable via the gear icon; the Android hardware back button returns to the list. |

Every screen is built as a deliberate set of states — **loading**, **empty**, **error** and **full** — rather than only the happy path. The error state exists because a corrupted `localStorage` value would otherwise blank the app with no recovery path.

## Features

- **Offline only.** No server, no network permission needed at runtime. Notes live in `localStorage`.
- **Share to any app** via the native Android share sheet (WhatsApp, SMS, email, Bluetooth).
- **Copy** to the system clipboard, with a confirmation toast.
- **Swipe to delete with undo.** Deletions are recoverable for 5 seconds and restore at their original position.
- **Native haptics** through the Capacitor Haptics plugin, respecting the in-app setting.
- **Inline editing** — tap, type, press Enter to save or Escape to cancel. Emptying a note and leaving deletes it.
- **Relative timestamps** (`Now`, `12m ago`, `Yesterday`, `Tue`, `14 Mar`) and per-note word counts.
- **Data model** — notes are stored as `{ text, created }`, with automatic migration from the earlier plain-string format.

## Tech

| Layer | Choice |
| --- | --- |
| UI | Vanilla HTML, CSS, JavaScript — no framework |
| Native bridge | Capacitor 8 |
| Native plugins | Haptics, Share, Clipboard |
| Android | Gradle, `minSdk 24`, `compileSdk 36` |
| Build target | JDK 21, Android SDK command-line tools |

## Running it

```bash
npm install
npx cap sync android          # copy web assets into the native project
npx cap run android           # build, install, and launch on a device
```

A USB-debugging-enabled device or emulator must be connected. To open the project in Android Studio instead:

```bash
npx cap open android
```

### Everyday workflow

Edit `www/index.html`, then:

```bash
npx cap sync android
npx cap run android
```

Never edit `android/` for web changes — it is generated by Capacitor, and the next sync will overwrite it. The exceptions are the native resources: the launcher icon, splash screens, colours and themes.

## Built under a hardware constraint

This was developed on an **8GB RAM laptop with a 2017 i5**, which cannot run an Android emulator. Rather than upgrade the machine, the workflow avoids the emulator entirely:

- The Android SDK and JDK 21 were installed by hand through the command-line tools — no Android Studio.
- The app is deployed straight to a physical phone over ADB.
- The phone screen is mirrored to the desktop with [scrcpy](https://github.com/Genymobile/scrcpy).

That constraint is also why the web layer stays framework-free: Vite, Angular and React Native toolchains all have real memory costs, and this setup had none of them to spare.

## Lessons from the build

Notes gathered while getting this running, since most of them are not in any tutorial:

- **`compileSdk` must be at least as high as the highest `compileSdkVersion` any AndroidX dependency requires.** Capacitor 8 pulls in activity 1.11 and core 1.17, which need API 36. Compiling against 34 fails with an AAR metadata error.
- **`navigator.vibrate` is unreliable inside an Android WebView.** Use the Haptics plugin, and declare `android.permission.VIBRATE` in the manifest — without it, calls succeed silently and nothing happens.
- **Not every Capacitor plugin needs a manifest permission.** Share and Clipboard use intents the user grants implicitly; Haptics does not.
- **Skip `npx cap sync` and plugins will appear "broken."** The sync step is what registers native code with the app.
- **Dismissing the Android share sheet rejects its promise.** That is a user action, not an error, so it should not surface as a failure.
